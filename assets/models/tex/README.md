# District palettes (colormap variants)

Drop-in replacements for the embedded `colormap` texture of the packed kits. Same size (512×512) and
layout as Kenney's original, so every UV keeps working — swap `material.map` and the whole kit
changes colour without new geometry. Generated by `tools/palettes.py` (edit the hex values there and
re-run); preview renders in `tools/shots/palette-*.png` (`palette-original.png` = Kenney colours).

## Using them in three.js

```js
const t = new THREE.TextureLoader().load('assets/models/tex/commercial-oldtown.png');
t.flipY = false;                      // glTF UV convention - REQUIRED, otherwise everything samples the wrong row
t.colorSpace = THREE.SRGBColorSpace;  // the PNGs are sRGB colour, like the embedded ones
// filtering: same as the GLB sampler (mag Linear, min LinearMipmapLinear) = TextureLoader defaults.
const mat = kitMaterial.clone(); mat.map = t;   // one material per district → one draw call per kit per chunk
```

A district can alternate two variants of the same kit (e.g. `-oldtown` / `-oldtown-b`) per building
group for variety at the cost of one more draw call per chunk.

## How a Kenney colormap is laid out

512×512 = **4 rows × 16 half-cells**. A half-cell is 32 px wide × 128 px tall: pixel rect
`x = hc*32 … hc*32+31`, `y = row*128 … row*128+127` (row 0 at the top of the PNG; glTF UV v=0 is the
top, so `v = y/512`). Each half-cell is either **flat** or a **vertical gradient** (light at the top →
darker at the bottom). The models sample `u` at the half-cell centre (`hc*32+16`) and run `v` along a
face — e.g. a wall goes from v≈row*128+12 at its top edge to ≈+102 at its bottom — which is how Kenney
bakes the soft vertical shading. Every UV sits at least 12 px inside its half-cell, so there is no
bleeding with linear filtering or mipmaps at normal viewing distances.

Cells marked *(variant)* are the ones `tools/palettes.py` recolours; everything else is Kenney's.
